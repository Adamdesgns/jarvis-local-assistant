## 2. THE TERMINAL stage 2 — built, except the visible half

Roadmap's topmost unchecked item. **The box is still unchecked**, on purpose.

### What works

**The classifier** — `src/command-guard.js`, 27 tests. Every command you type
gets one of three verdicts, same vocabulary as the screen guard:

- **free** — read-only, runs immediately. `dir`, `git status`, `ipconfig`.
- **approve** — stops for a confirm card. `npm install`, `del notes.txt`,
  `git push`, `node script.js`.
- **deny** — refused outright, no card offered. `format c:`,
  `vssadmin delete shadows`, `reg delete`, `net user`, `runas`, `shutdown`.

The design decision worth knowing: **there is no explicit approve list.**
`approve` is what a command gets by falling through everything else. So a
command nobody thought about asks instead of running, and the only way to make
something silent is to add it to the free list in shipping code. Fail-closed by
construction rather than by remembering to.

It also splits on every chaining operator and takes the worst segment, so
`dir && format c:` is denied rather than read as a harmless `dir`. That's the
hole a first-word-only classifier leaves wide open.

**The runner** — `core/command-runner.js`, 18 tests. Follows `tool-service.js`'s
pattern: argv array, `shell:false`, `windowsHide`. Three details worth calling
out:

- It passes `/d`, which skips the AutoRun registry key. Without it, anything
  sitting in `HKCU\...\Command Processor\AutoRun` executes ahead of your command
  every single time.
- A hung process gets **killed**, not just reported. Default ceiling 90s.
- Output is capped at 256 KB so a runaway loop can't grow the log until the
  window dies.

**The confirm card is structural, not conventional.** An approve-tier command
that arrives without an explicit "yes" is refused by the runner itself. So if
the renderer ever forgets to show the card, you get a refusal — not a silent
`npm install`. `approved: true` still doesn't rescue a denied command; deny has
no card at all.

**The name collision is settled.** The roadmap flagged this as a stage-2
blocker: `core/defaults.js` registered an app literally called `terminal`
pointing at `wt.exe`, while the console module is also called terminal. My call,
made while you were asleep — inside JARVIS **"terminal" means the console**, and
the external app is now **"windows terminal"** (alias `wt`). The ambiguous word
never reaches an external shell, because a real shell outside the guard has no
confirm card at all.

⚠️ **This changes the defaults only.** If your live `settings.json` already has
the old `terminal` key saved, it keeps it until someone writes a migration. So
on your machine "open terminal" may still launch Windows Terminal until then.
Worth a look when you next open Settings.

**Wiring** — `terminal:classify`, `terminal:run`, `terminal:cwd` in `main.js`
plus the `preload.js` bridge. `cd` is honoured only inside your approved
folders; with no approved folders it refuses and tells you to add one. Every
command run **and every refusal** goes to the activity log.
